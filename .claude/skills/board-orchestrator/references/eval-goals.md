# Cera 평가 목표 — 무엇에 쓰고, 무엇을 누가 재나

리더는 Phase 2 에서 WP 마다 아래 용도(U) 하나 이상을 적고, Phase 4–5 에서 이 표의 기준으로 판정한다.
수치는 초깃값이다. 바꾸면 이 파일을 고치고 `CLAUDE.md` 변경 이력에 한 줄 남긴다.

## 1. 용도 (누가 · 언제 · 성공)

| # | 용도 | 누가 · 언제 | 성공 |
|---|---|---|---|
| U1 | **회의 판서** | 2–5명이 Discord 로 말하면서, 데스크톱 + 폰. 가입 없이 링크만 | 링크를 열고 60초 안에 첫 획. 남의 획이 2초 안에 보인다. 회의가 끝날 때까지 그림이 사라지지 않는다 |
| U2 | **에이전트와 러프 → 구체화** | 한 사람이 Claude Code · Codex · Antigravity 세션을 켜 둔 채 대충 그린다 | 고르고 'AI 에게' → 원본 옆에 제안 → '바꾸기'. 손글씨 수식은 LaTeX 요소, 스케치는 편집 가능한 도식. 원본은 사람이 바꾸기 전까지 그대로 |
| U3 | **회의 중 구체화** | U1 도중 한 사람이 요청, 나머지는 보고 있다 | 요청 상태(대기 · 작업 중 · 제안 · 실패)가 모두에게 보인다. 두 사람이 동시에 바꾸기 · 버리기를 눌러도 그림이 깨지지 않는다 |
| U4 | **결과 들고 나가기** | 회의 · 작업 뒤, 에이전트나 사람이 | 보드 → 글(`board_read`) · mermaid · `.drawio` · PNG 로 나오고, 그것으로 계획 · 문서 · 코드를 이어 쓸 수 있다 |

### A. 코드 (WP 마다, 여러 라운드)

| 항목 | 기준 | 확인 방법 |

| 통과 | 두 리뷰어 모두 `막음 0 · 고침 0` (최대 3라운드) | 리뷰 파일 맨 위 판정 줄 |

### B. 에이전트 상호작용 (통합 전 1회, 고친 뒤 실패 항목만 다시)

고정 자료: `tests/fixtures/rough07.json`(흐름도 · 무향 그래프 · 수식 F1–F4 가는 펜/굵은 펜 · 메모, 11 영역).
에이전트 역할은 **맥락 없는 새 에이전트**가 `_workspace/tests/mcpc.py` 로 MCP 도구만 쓴다. 정답을 아는 쪽은 판독에 끼지 않는다.
판독 모델: Opus medium 은 꼭 한 번. 쓸 수 있으면 Luna · hydrogen 도 한 번씩 돌려 모델별 줄을 따로 적는다(실제 Codex · Antigravity 를 대신하지는 못한다 — 참고값).

| 측정 | 기준 |
|---|---|
| 왕복 시간(요청 → 제안 카드) | ≤ 90초, 목표 10–30초. 구간별(요청 → 작업 중 → 제안 → 바꾸기) 실측값을 적는다 |
| 도구 호출 수(요청 하나) | ≤ 6 |
| 흐름도 인식 | 노드 6/6(모양 · 라벨), 간선 ≥ 5/6(방향 · yes/no) |
| 무향 그래프 인식 | 노드 5/5, 간선 ≥ 5/6, 화살촉 0 |
| 수식 인식 | 가는 펜 ≥ 3/4, 굵은 펜 ≥ 3/4 또는 틀린 글자를 `uncertain` 으로 표시 |
| 원본 보존 | '바꾸기' 전 원본 요소 version 불변. 실패 시 카드 없음 + 칩에 이유 한 줄 |
| 스냅샷 비용 | 장당 추정 토큰을 적는다(기준선 0.1–1.4k) |
| 에이전트 없음 | 요청이 남아 있다가 나중에 켠 세션이 이어서 끝낸다 |

세부 시나리오(E1–E8)는 `_workspace/09_plan.md` (d)절. 합성 손글씨라서 이 수치는 "배관이 된다" 의 증거다. 실제 정확도는 D 에서 본다.

### C. 처음 써 보는 사람 리뷰 (스모크 통과 뒤)

읽어도 되는 것: `README.md`, `docs/guide.md`, `skills/cera/SKILL.md`, `cera --help`, MCP `tools/list`, 화면.
읽으면 안 되는 것: `web/src` · `server/` · `tests/` · `_workspace/0[0-4]*` · 리뷰 파일. 과제 문장 말고는 힌트를 주지 않는다.

| # | 과제(이 문장만 준다) | 용도 | 맡는 쪽 |
|---|---|---|---|
| N1 | 보드를 하나 열고 다른 사람에게 줄 링크를 얻어라 | U1 | Luna(CLI · MCP) |
| N2 | 링크로 들어가 이름을 넣고, 선 하나와 글 하나를 남겨라. 다른 창에서도 보이는지 확인하라 | U1 | hydrogen(브라우저, 데스크톱 + 폰 크기) |
| N3 | 보드에 대충 그려진 흐름도를 깔끔한 도식으로 바꿔라(원본은 남겨라) | U2 | 둘 다 — hydrogen 은 화면에서 요청, Luna 는 에이전트로 처리 |
| N4 | 손으로 쓴 수식 하나를 고칠 수 있는 수식으로 바꿔라 | U2 | Luna |
| N5 | 다른 사람이 낸 요청이 지금 어떤 상태인지 화면만 보고 말하라. 제안을 버렸다가 되돌려라 | U3 | hydrogen |
| N6 | 보드 내용을 문서에 붙일 수 있는 형태로 꺼내라(글 · 도식 · 그림 중 둘) | U4 | Luna |

| 측정 | 기준 |
|---|---|
| 도움 없이 성공 | 과제마다 `혼자 됨 / 문서를 다시 보고 됨 / 안 됨`. 목표: 6개 모두 '안 됨' 없음, '혼자 됨' ≥ 4 |
| 시도 수 | 과제마다 헛손질(틀린 클릭 · 틀린 명령 · 오류 응답) 횟수. 3회를 넘으면 헷갈린 곳으로 적는다 |
| 헷갈린 곳 | `어디서 · 무엇을 기대했나 · 실제로 무엇이 나왔나` 한 줄씩, ≤ 8개 |

처리: '안 됨' 과 두 모델이 같이 짚은 곳은 Phase 3 으로 돌린다. 한 모델만 짚은 곳은 D 의 질문 후보다. 이 리뷰는 사람의 사용감 판정을 대신하지 않는다.

### D. 사람 확인 (≤ 10항목, 통합 직전)

리더가 아래에서 고르고, C 에서 나온 질문 후보로 바꿔 끼운다. 형식은 `board-uiux-test` 의 요청서.

| # | 해 볼 일 → 보여야 하는 것 | 용도 |
|---|---|---|
| H1 | 폰에서 링크를 열고 이름을 넣어 첫 획까지 → 막히는 화면이 없다 | U1 |
| H2 | Discord 통화 중 두 사람이 같이 그린다 → 상대 획이 바로 보이고 내 획이 밀리지 않는다 | U1 |
| H3 | 실제 펜(iPad · S Pen)으로 대충 그린 흐름도를 고르고 'AI 에게' → 버튼을 바로 찾는다 | U2 |
| H4 | 기다리는 동안 → 지금 무슨 상태인지 알 수 있고, 기다림이 참을 만하다 | U2 · U3 |
| H5 | 제안이 원본 옆에 뜬다 → 바꾸기 · 원래대로가 기대한 대로 된다 | U2 |
| H6 | 실제 손글씨 수식 3개 → LaTeX 가 맞고, 틀린 곳은 고칠 수 있다 | U2 |
| H7 | 폰에서 요청 · 제안 화면 → 버튼이 가려지거나 겹치지 않는다 | U3 |
| H8 | 에이전트를 안 켠 채 요청 → 무엇을 해야 하는지 안내가 이해된다 | U2 |
| H9 | 결과를 mermaid 나 PNG 로 꺼내 문서에 붙인다 → 손볼 것 없이 쓸 수 있다 | U4 |
| H10 | 다음 회의에서 또 쓰겠는가, 가장 거슬린 것 하나 | 전체 |

답 칸: `좋음 / 이상함 / 안 됨` + 한 줄. 답이 없는 항목은 '통과' 가 아니라 '확인 못 함' 으로 보고한다.
