# board-review

먼저 `git diff main...HEAD --stat` 와 해당 파일 diff 를 읽는다. 구현자 메모(`03_impl_*`)는 지적 목록을 다 쓴 뒤에만 읽는다.

## 점검표
1. **받아들일 기준** — `02_plan.md` 의 문장 하나하나가 코드로 실제 가능한가.
2. **동기화** — 새 상태가 요소/파일로 저장되는가, 로컬 state 에만 있지 않은가. version 을 안 올린 수정, 파일 업로드 누락, 두 사람이 동시에 고칠 때 덮어쓰기.
3. **폰 · 터치** — 760px 이하 · coarse pointer 에서 보이는지/숨기는지, 터치 핸들러에서 동기 focus, 버튼이 겹치거나 화면 밖으로, hover 전용 UI.
4. **IME · 단축키** — 한글 조합 중 Enter/단축키가 먹히는지(`isComposing`), 입력창 안 단축키가 보드로 새는지.
5. **보기 전용** — view role 에서 편집이 가능해지는 구멍.
6. **성능** — 첫 화면 번들에 무거운 것이 들어왔는가(`npx vite build` 출력의 index-*.js 크기를 main 과 비교), onChange 안의 무거운 계산, 펜 입력 중 지연.
7. **라이선스** — 옮긴 코드 · 새 의존성 · 글꼴의 라이선스와 고지.
8. **보안** — 사용자 입력을 innerHTML/SVG 로 넣는 곳(XSS), data URL 종류, 서버 쪽 크기 제한.
9. **회귀** — 기존 기능(글 입력 시트, 수식, PNG 저장, 메뉴, 초대 링크)이 깨질 수 있는 변경.

## 심각도
- **막음**: 데이터 손실 · 동기화 깨짐 · 보안 · 빌드 실패 · 기준 미충족.
- **고침**: 특정 기기 · 조건에서 기능이 안 됨, 눈에 띄는 UI 깨짐.
- **사소함**: 이름 · 문구 · 작은 정리(판정에 영향 없음).
